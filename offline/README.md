# Offline Cold Replay Suite

Operator-focused entrypoint for offline replay proof runs.

Full runbook: `docs/OFFLINE_REPLAY_HARNESS.md`

## Quick Start

### 1) Preflight

```bash
jcs-offline-replay preflight --matrix offline/matrix.yaml
```

### Matrix introspection (machine-readable)

```bash
jcs-offline-replay inspect-matrix --matrix offline/matrix.yaml
```

### 2) Single-architecture full proof run

```bash
jcs-offline-replay run-suite --matrix offline/matrix.yaml --profile offline/profiles/maximal.yaml
```

### 3) Cross-architecture full proof run

```bash
jcs-offline-replay cross-arch
```

### 4) Cross-architecture + full offline official vectors (including ES6 100M)

```bash
jcs-offline-replay cross-arch \
  --run-official-vectors \
  --run-official-es6-100m
```

## Key Contracts

- x86_64 matrix: `offline/matrix.yaml`
- arm64 matrix: `offline/matrix.arm64.yaml`
- x86_64 maximal profile (local): `offline/profiles/maximal.yaml`
- arm64 maximal profile (local): `offline/profiles/maximal.arm64.yaml`
- x86_64 server matrix (IaC-backed): `offline/matrix.server-x86_64.yaml`
- arm64 server matrix (IaC-backed): `offline/matrix.server-arm64.yaml`
- x86_64 server profile (IaC-backed): `offline/profiles/server-linux-x86_64.yaml`
- arm64 server profile (IaC-backed): `offline/profiles/server-linux-arm64.yaml`
- evidence schema v1: `offline/schema/evidence.v1.json`
- evidence schema v2: `offline/schema/evidence.v2.json`
- infra manifest schema: `offline/schema/infra-manifest.v1.json`

## Evidence Schemas

### evidence.v1

Used for local and CI runs. Binds evidence to source commit, binary, matrix, profile,
and vector bundle.

### evidence.v2

Used for server-backed runs on provisioned cloud hardware. Extends v1 with three
required infrastructure binding fields: `infra_manifest_sha256`, `infra_repo_url`,
`infra_repo_commit`. Node replay items may include optional discovered substrate
fields: `discovered_cpu`, `discovered_kernel`, `image_digest`.

Evidence v2 is emitted automatically by `jcs-offline-replay` when
`RunOptions.InfraManifestSHA256` is populated. `evidence.v1` remains the valid
local/CI format; node-level v2 fields are rejected from v1 evidence.

### infra-manifest.v1

Records the IaC-provisioned substrate identity for a conformance run. Fields:
- `infra_repo_url` + `infra_repo_commit`: the IaC repo at the exact commit used
- `provider_engine` + `provider_version`: e.g., `"opentofu"`, `"1.8.0"`
- `provider_lock_sha256`: SHA-256 of `.terraform.lock.hcl`
- `hosts`: per-host records with role (`x86_64`/`arm64`), `cloud_provider`, `region`,
  `instance_type`, `image_id`; optional `discovered_cpu` and `discovered_kernel`

The infra manifest is generated by the IaC layer, not the harness. It is a separate
artifact bound into evidence via `infra_manifest_sha256`.

## Server-Backed Profiles

Server profiles (`server-linux-x86_64.yaml`, `server-linux-arm64.yaml`) include
`infra-substrate-binding` in `required_suites`. When a profile requires this suite,
`ValidateEvidenceBundle` rejects evidence that is not v2. This enforces that
server-backed runs always carry infrastructure identity binding.

### Container Image Pre-Resolution

For server-backed runs, the provisioned host MUST resolve mutable image tags to
digest references before executing the replay matrix:

```
debian:12-slim  →  debian@sha256:<64-char-hex>
```

Server matrices carry stable env indirection and the operator workflow injects
the resolved digest-pinned image reference at runtime. Post-replay discovery
records the actual image digest in each `node_replays` entry via `image_digest`.

## Server-Backed Release Gate

For server-backed evidence (v2) with infra manifest binding:

```bash
JCS_OFFLINE_EVIDENCE=$(pwd)/offline/runs/releases/<tag>/x86_64/offline-evidence.json \
JCS_OFFLINE_INFRA_MANIFEST=$(pwd)/offline/runs/releases/<tag>/infra-manifest.v1.json \
JCS_OFFLINE_CONTROL_BINARY=/abs/path/to/release-control/jcs-canon \
JCS_OFFLINE_MATRIX=$(pwd)/offline/matrix.server-x86_64.yaml \
JCS_OFFLINE_PROFILE=$(pwd)/offline/profiles/server-linux-x86_64.yaml \
JCS_OFFLINE_EXPECTED_GIT_COMMIT=<release-commit-sha> \
JCS_OFFLINE_EXPECTED_GIT_TAG=<tag> \
go test ./offline/conformance -run TestOfflineReplayEvidenceReleaseGate -count=1
```

## Outputs to Audit

Each full run emits an `offline/runs/...` directory containing:

- immutable bundle (`offline-bundle.tgz`)
- replay evidence (`offline-evidence.json`)
- controller logs (`logs/*.log`)
- audit summaries (`audit/audit-summary.md`, `audit/audit-summary.json`)
- checksums (`audit/bundle.sha256`, `audit/evidence.sha256`)
- run index (`RUN_INDEX.txt`)

`offline/runs/...` is operator-local output and is intentionally not tracked in
git.
